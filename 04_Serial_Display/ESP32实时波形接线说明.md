# ESP32-S3 v05：BLE、录音与串口屏波形原型

2026-10-13。配套Nano 20K R11（R9/R10的原I²S输出也兼容）、App v0.5.0、淘晶驰TJC8048X550_011C。

这是实际FPGA数字音频波形显示原型。声音仍在FPGA合成；ESP32抽取真实PCM并生成绘图点，屏幕显示。当前未实现FPGA内部波形捕获/图形生成、FFT或李萨如，不能据此宣称已完成赛题“基于FPGA硬件逻辑实时生成可视化反馈”的完整验收。

## 接线

断电后接线，保持已有FPGA↔ESP32 UART、I²S和共地不变。

| ESP32-S3 | 串口屏 |
|---|---|
| GPIO8（UART2 TX） | RX |
| GPIO9（UART2 RX） | TX |
| GND | GND |

必须断开USB转TTL模块的TX/RX，不能让模块TX与ESP32 TX同时连到屏幕RX。USB转TTL可继续仅作为已验证的5V供电来源，但需保留其GND并确保供电稳定；不要把它的5V电源接到ESP32的GPIO或3V3。也可改用独立稳定5V电源，所有信号共地。
使用已验证的TTL接口，不接RS232电平。

原音频输入：Nano56→ESP4(BCLK)、Nano55→ESP5(WS)、Nano54→ESP6(DATA)。不要接功放喇叭输出。
原UART：ESP17→Nano52、ESP18←Nano53。

## 屏幕程序

沿用`D:/ESP32_S3_N16R8/tjc_display_v01/instrument_display.HMI`，page0含s0，760×200，0通道。
已实测COM7、s0.id=1、760×200，逐点正弦显示正常。批量addt的FE准备/FD完成握手已实测；运行时baud=115200及控件查询已实测。
v05自动识别115200或9600，再临时切换115200；不修改屏幕HMI源码或永久波特率配置。
屏幕程序、FPGA和App均无需为本次波形原型更新。

## 操作和验收

固件更新并接线后，保持FPGA输出I²S。按住实体键至少一秒，观察波形；依次换音色、换八度、改变压力。
无音符时应为中线；有音符时出现周期曲线。音高升高时同一窗口内周期数应增加；音色变化应改变形状；音量变化应改变高度。
每帧显示760个连续采样，约16.21ms；首个上升过零点触发对齐，无触发时从窗口起点显示。固定幅度刻度，不作自动归一化。
显示刷新以若干帧每秒为目标，并不等于46,875Hz音频采样率；短促点按可能被低刷新率略过。
超过约1.2秒没有新PCM时清除曲线，避免旧波形被误认为实时信号。
显示数据采用单项最新帧队列：屏幕慢时丢旧显示帧，不丢录音PCM。屏幕缺失或断线不应阻断BLE控制与录音。
录音仍由唯一I²S任务采集。空闲时间歇抓取显示窗口，接到录音请求后转入连续录音；请求恰逢预览时，开始采集可能增加一次预览等待，正常有时钟时通常为一个1024帧窗口约22ms，无时钟时单次读超时100ms。
录音停止/CRC计算时显示可能暂停，完成后恢复预览。原BLE协议、30秒缓存、CRC32及窗口下载不变。

建议验收：持续触摸波形、C4/C5/C6周期变化、四音色外形、录音并下载、屏幕断线后手机仍可控制、断开I²S时清图。
真实链路和手机功能仍须上板验收，单元测试不能替代。

## 构建与烧录

在本目录执行：

```powershell
python ..\idf_local.py -B build_local build
python ..\idf_local.py -B build_local -p COM6 flash
```

本机USB串口可能变化，COM6需以实际识别结果为准。新构建输出`build_local/ble_uart_bridge.bin`、bootloader和partition_table；三者均来自本目录。交付的`build_direct`为已编译输出，原构建缓存含工作区绝对路径，因此在交付目录修改源码后要使用新的`build_local`目录构建。
烧录后查看启动日志确认PSRAM与广播正常；接屏幕后应出现`LCD_WAVE: Screen online`与`Live I2S frames sent`。
若需回退，使用原`ble_record_bridge_v04`构建输出，不要混用不同目录的分区与应用文件。
