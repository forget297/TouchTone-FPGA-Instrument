# R13 本地32音与FPGA实时可视化

本目录是从 2026-10-19 交接包的 FPGA R12、ESP32 v06、串口屏 HMI 分离出的新版本。原交接文件未修改。

**交付状态：FPGA R13 已完成综合、布局布线、时序检查并生成码流；ESP32 v07 已完成源码和主机侧协议/绘图测试，但尚未完成 ESP-IDF 目标固件编译，也未进行实物烧录和串口屏联调。不要将本包标为整机上板验收通过。**

## 1. 新增操作

S2 复位进入普通演奏模式 MODE 0，菜单0。短按编码器按下再松开计一次，菜单由原来的8项扩展为10项，0→…→9→0。菜单0～7原功能保留，因此现在返回菜单0需要短按10次，不再是8次。指引模式中的按钮含义保持原设计。

|菜单|从复位短按次数|旋转编码器|其他操作|
|---|---:|---|---|
|0～7|0～7|原音色、ADSR、wet、叠层、曲目功能|沿用原操作|
|8|8|在32个半音中前后选音：00=C4，31=G6，首尾循环；每次选音触发约800ms门控|短按摇杆：当前音持续门控开/关；长按编码器≥800ms：32音同时持续发声开/关|
|9|9|四种显示循环：波形→频谱→李萨如→声部表|在声部表中短按摇杆：翻页，每页8音，共4页|

- 菜单8的初始选择是C4；按摇杆可听C4，旋转一步会选择下一个半音。
- 逐音试听用当前音色和ADSR。类拨弦预设Sustain=0，即使门控保持，声音也会自然衰减；这不是门控失效。起音/释音设置很长时，听到的时长不等于800ms门控时长。
- 逐音试听期间固定基准音高，暂停全局滑音/颤音对引擎的偏移；若要只听一个音，请关闭菜单6叠层、菜单5延迟，并松开其他触摸音/手机按键。
- **32音同时模式使用C4～G6实际音符表、正弦音色、固定包络、降低后的混音增益，并旁路延迟效果。** 不使用原MODE 1的测试频率表。所有声部仍经相位累加、包络和实时混音，不播放录音。
- 32音同时模式可跨菜单保持，以便进入菜单9查看频谱/声部表；屏幕`ALL 1`表示开启。回到菜单8长按编码器、短按摇杆或旋转选音可退出。切换模式或S2复位也会退出。退出后包络尾音/音色平滑需要短暂时间恢复。
- 仅单音试听的门控在离开菜单8时关闭。要看某音的指定视图，先在菜单9选视图，再回到菜单8试听；视图会保留。

## 2. 屏幕内容的真实含义

屏幕沿用TJC8048X550_011C，800×480。仍通过ESP32 UART2连接。FPGA负责分析与数据生成，ESP32只接收、校验、换算单位及绘图，没有在ESP32上计算DFT。

|页面|数据来源|显示与限制|
|---|---|---|
|波形|FPGA最终混音/效果后的有符号PCM，与I2S采样时刻对应|128点，每4个样本取一点，覆盖约10.84ms；8位垂直显示；这是抽点示波显示，不作带限重采样|
|实时频谱|同一最终PCM，经FPGA 1024点Hann窗及DFT|128频点，0～5813.60Hz，频点间隔45.776Hz；线性幅度、自动纵向缩放，显示最大谱线位置与近似幅度|
|李萨如|同一PCM的X[n]与X[n+16]|64对XY点，16样本相差约0.341ms。属于延迟相图；当前I2S左右声道相同，不冒充两个独立声道或可调XY振荡器|
|声部表|每声部实际相位增量、实际波表×ADSR输出峰值|每页8音，共32音；Hz=FCW×46875/2^32；AMP为该声部混音前数字峰值，ACTIVE为声部状态|

频率表中的Hz是硬件振荡器实时相位步进换算值，**不是对最终混音的逐音频率估计**。AMP在全局力度增益、音色补偿、32路相加和延迟效果之前采集，不能当成DAC端电压或各音最终声压。分母32768表示16位PCM满量程。`OUTPUT PEAK`则是最终混音数字峰值。`FAULT`反映音频帧超时或BLE回复FIFO溢出；传感器故障仍看原板载LED。完整32音基准见`32音频率表.md`。

频谱幅值用max(|Re|,|Im|)+3/8 min(|Re|,|Im|)近似，并补偿Hann窗相干增益；存在近似误差、频点偏移误差和泄漏，不用于精密幅度标定。1024点对应约21.85ms分析窗，**不能分辨C4附近所有相邻半音，因此本屏幕频谱不能充当32个独立峰全部可见的赛事证据**；32音现场验证仍需更长窗的外部音频分析。声部表可确认32个活跃状态，但不能替代声学证据。

FPGA快照目标周期250ms（约4Hz），采集和分析完全旁路，不阻塞音频；UART/屏幕绘图较慢时，ESP32只保留最新完整快照，屏幕实际刷新率低于快照率，需实机测量。页面初次进入要绘制内置字体，可能明显慢于后续刷新。断开FPGA数据后显示WAITING提示。

- `tests/`：协议与绘图主机测试、数值核对脚本、四张由真实绘图命令渲染的预览。预览使用仿真注入数据，不是实物照片；声部测试故意给每lane相同FCW以核对通道映射。

屏幕程序沿用旧HMI，但ESP32运行时隐藏原组件，用fill/line绘制完整四页，并自带5×7字形，不依赖屏幕字体资源。出于兼容性，屏幕文字暂用英文。实屏仍需确认`vis 255,0`、`fill`、`line`指令及绘图性能；这些尚未实机验证。

## 4. 构建和接线

FPGA：在`fpga`目录使用Gowin Education V1.9.11.03执行`gw_sh.exe build.tcl`，器件GW2AR-LV18QN88C8/I7。当前包已生成对应码流，不必为了查看源码重新综合。

ESP32：在已安装ESP-IDF **6.0.2** 且导出环境的终端中，进入`esp32`目录执行：

```text
idf.py set-target esp32s3
idf.py build
```

成功后再用实际串口执行`idf.py -p COM实际编号 flash monitor`。本次没有执行烧录。本机未找到SDK，尝试下载GitHub官方仓库失败（连接github.com:443超时），所以尚未验证IDF编译、链接大小和真实驱动运行；主机stub测试不能覆盖这些内容。

沿用原接线，无新增FPGA引脚：

|连接|引脚|
|---|---|
|FPGA→ESP32数据|Nano53/TX→ESP GPIO18/RX|
|ESP32→FPGA控制|ESP GPIO17/TX→Nano52/RX|
|ESP32→串口屏|GPIO8/TX→屏RX；GPIO9/RX←屏TX|
|音频|Nano56/BCLK、55/WS、54/DATA，沿用DAC和录音接线|
|串口参数|两条链路均115200、8N1；屏端启动兼容9600探测|

共地，屏幕沿用原稳定5V电源；UART电平按原接线设计保持。不要把音频55脚改作LED。

## 5. 上板验收步骤

1. 完成v07目标编译，备份原烧录文件，再配套升级FPGA/ESP32。屏幕保持原HMI。复位后确认出现`FPGA R13`、FS46875、FAULT0，而不是WAITING。
2. 普通模式短按8次，摇杆按一下，听C4；旋转检查全部32音，首尾C4≈261.626Hz、G6≈1567.982Hz。关闭叠层、wet并使用稳定音色。与外部音频FFT/调音器逐一对照；不能只看屏幕Hz就认定DAC音高已验收。
3. 菜单8长按编码器≥800ms，检查ALL1；短按进入菜单9，选择声部表，摇杆翻遍4页，确认32个ACTIVE、32个预期Hz和非零AMP。再用外部较长窗FFT验证同时音频，观察无削顶、无掉帧。停止时验证ALL0及声音消退。
4. 菜单9选波形，输入单音，观察有波形、松开后消退；选择频谱，分别试听低/高音和双音，谱峰位置应移动并与频点分辨率相符。静音频谱应接近零。高音色谐波会产生多个谱峰，不能把每个谐波算作独立声部。
5. 选李萨如，同一正弦音应出现稳定椭圆/近直线，相位由频率与固定延迟决定；换音或和弦后图形应变化。确认不是播放预置动画。
6. 声部表：用持续音色演奏，检查对应ACTIVE和AMP变化；松开后Release阶段AMP逐渐降低。压力改变最终输出峰值而未必改变混音前AMP，这是测量位置不同的正常结果。
7. 在显示刷新期间测试App音符、键位设置、曲谱、录音开始/停止及回传，确认新二进制可视数据未泄漏到App回复。连续演奏检查FAULT始终0、无爆音、音频WS保持46.875kHz。
8. 拔掉FPGA→ESP数据线，屏幕应显示WAITING；恢复后应自动显示最新数据。单独复位屏幕/ESP32，确认能重连并重新绘制。

## 6. 实现细节与已知边界

分析器使用4路引擎声部遥测、1024点原始采样/窗后缓存、共享乘加器DFT，以及单写口可视数据缓存。最终数据736字节，被分成23个42字节包：A8、协议1、帧号、类型1、偏移LE16、长度32、载荷32、CRC16-CCITT LE16、5A。CRC初值FFFF、多项式1021，覆盖前39字节。旧A5回复仍为8字节。

UART仲裁保持完整42字节包不可打断，控制回复在包之间优先；单个可视包占线约3.65ms。该仲裁延迟只影响回传，不阻塞接收演奏命令或FPGA音频合成。连续控制流可能降低可视刷新率。ESP32验证校验和、CRC、分片顺序及帧号，完整帧才发布。

新增功能未声称降低传感器或DAC延迟。原引擎数字链路回归测试不等于整机≤5ms实测。当前布局布线仍保留原工程的通用时钟路由警告；27MHz同步时序通过不替代I2S外部接口和硬件接线的现场验证。
