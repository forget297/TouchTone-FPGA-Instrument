# ESP32-S3录音固件v04与配套App说明

更新日期：2026-10-11。配套FPGA R9、ESP32录音固件v04。

## 更新与使用

ESP32工程 D:/ESP32_S3_N16R8/ble_record_bridge_v04，应用 D:/ESP32_S3_N16R8/android_app_v04。
覆盖安装 FPGA_Instrument_Assistant_v0.4.0.apk，再重新连接 FPGA_BLE_UART。
现有FPGA R9和接线无需改变，采样率仍为46,875Hz、单声道16位，手动录音上限30秒。
本次ESP32已在COM6烧录并校验成功；启动日志确认PSRAM自检通过、30秒缓存可用、蓝牙广播正常。无需用户再次烧录。
用户已反馈新版下载速度快了很多。可用同样长度的3～5秒录音记录量化耗时；完成提示中显示下载时间。
蓝牙传输速度与手机、距离和无线干扰有关，用户已反馈明显加速，但尚未量化倍数。

## 下载加速

旧版每约237字节PCM需一次写请求和一次读回复；30秒PCM为2,812,500字节，需要约11,868个逐包往返。
新版一次请求让ESP32连续通知最多16包，每包附绝对偏移、窗口序号和XOR校验；MTU247时单包236字节PCM。
应用收齐一组再请求下一组，缺包时从连续有效数据的末尾重试，最终还需整段CRC32正确才生成WAV。
下载期间请求安卓高优先级连接，完成或失败后恢复普通连接优先级。
若旧ESP固件不支持高速命令，或多次窗口重试失败，自动改为兼容下载。不会降低采样率或使用有损压缩。
通知复用已订阅的控制特征def1；录音命令仍走def2，不增加GATT特征或描述符，协议设计不要求新增服务缓存。
传输过程中保持应用前台。录音期间实体演奏保持独立；应用其他控制操作仍暂停。

## 录音管理

录音页点击“录音管理（播放／导出／删除）”，查看已下载的录音、时长和文件大小。
选择一条可播放、导出或删除；“清空全部录音”会二次确认。
每次成功下载用独立时间戳文件名保存，不再覆盖上一条录音；应用重启可继续看到保存内容。
兼容识别旧版fpga_recording.wav，旧版曾被覆盖的更早录音无法恢复。
删除的是应用内部保存的文件；通过“导出为WAV”复制到其他目录的文件仍保留，需要用手机文件管理器删除。
下载未完成或CRC失败不会生成新录音，不影响之前保存的文件。

## 协议补充

录音命令46：arg/lo/hi为24位小端起始字节偏移，要求录音就绪且控制通知已订阅。
控制应答保持A6格式，payload为4字节小端窗口结束偏移（不含末尾）。
音频通知格式：A7 seq offset0 offset1 offset2 n PCM[n] XOR前面所有字节 5A。
单包n≤min(236,MTU-11)，一个窗口最多16包。最后一包可短包。
通知的seq与对应46命令相同。忽略旧窗口通知/重复数据，不把有空洞的数据当作完整。
发包任务遇到NimBLE缓冲区不足会等待并重新分配；不重复释放已被NimBLE消费的mbuf。
窗口发送期间拒绝新录音/清缓存，防止正在传输的PCM被覆盖。断线取消发送并保留录音缓存。
旧40/41/42/43/44/45命令保持兼容。

## 蓝牙和录音接线

数字均为板上对应的FPGA封装脚号/丝印，不是从排针一端数孔位。
断电后接线，两块板共地，分别USB供电，不额外并联3V3或5V。

| Nano 20K | ESP32-S3 | 方向/用途 |
|---|---|---|
| 52，ble_uart_rx | GPIO17/TX | ESP→FPGA，115200、8N1 |
| 53，ble_uart_tx | GPIO18/RX | FPGA→ESP |
| 56，I2S BCLK | GPIO4 | FPGA输出→ESP输入 |
| 55，I2S WS/LRCK | GPIO5 | FPGA输出→ESP输入 |
| 54，I2S DATA | GPIO6 | FPGA输出→ESP输入 |
| GND | GND | 公共地 |

52/53与HDMI EDID信号共用，当前联调不插HDMI。
54/55/56同时连接板载功放的数字输入；ESP仅并联接收这些信号，不改作输出，不断开功放。
喇叭专用接口J4是功放OUTP/OUTN输出，与54/56不是同一网络，不能接到ESP输入。
录音为Philips I2S、左右各16位、46,875帧/秒、BCLK 1.5MHz；左右原本相同，取一路输出单声道WAV，不需要MCLK。
接线尽量短且牢固。EC11另用A→77、B→41、KEY→29，不与新增录音线共用。

## App完整操作

### 连接与启动

1. 接线完成后上电，用programmer.exe的SRAM Program下载正式R9：
   `D:/FPGA创新赛/fpga_instrument_r9_ble_live/impl/pnr/fpga_instrument_r9_ble_live.fs`。
2. 若刚运行过编码器诊断，必须重新下载正式R9；诊断程序不提供声音和蓝牙UART乐器控制。
3. 手机覆盖安装`D:/ESP32_S3_N16R8/android_app_v04/FPGA_Instrument_Assistant_v0.4.0.apk`。
4. 关闭nRF Connect或电脑工具的连接，应用扫描并连接`FPGA_BLE_UART`，按安卓提示授予蓝牙相关权限。
5. 等待通信检查和键位读取完成，再开始操作。手机不需要先在系统蓝牙设置中配对。

ESP32 v04已于本次开发阶段在COM6烧录并校验成功，启动日志确认8MB PSRAM自检、30秒缓存及广播正常。通常无需重新烧录。
COM6只是当前电脑枚举结果，后续插拔可能变化，以实际设备为准。
FPGA SRAM程序掉电丢失，重新上电要重新下载；S2复位不会清除SRAM位流，但会恢复临时曲谱、键位及演奏参数。

### 演奏

主板保持普通演奏模式。演奏页上方12键支持按下、长按和松开；下方保留一秒试听和C4五秒试听。
长按时App约每1.8秒续时；松开立即发送释放。断线/强杀时，最后一次续时后的5秒内FPGA释放远程门控，允许包络/延迟尾音。
“停止远程音符”不关闭仍按住的实体触摸键。无线音高不经过实体键位映射，音色/叠层仍使用主板设置。
普通模式短按编码器循环八菜单，只有菜单0旋转调音色；S1切模式不会自动清菜单，S2恢复普通模式、菜单0。
四音色切换时建议松开再触摸比较，拨弦音色会自然衰减。无线传输不承诺达到本地触摸到发声10ms指标。

### 键位

松开所有实体触摸键，在“键位”页选择音高后点“应用”，App写入并读回核对。可恢复全部默认C4～B4。
两个触摸键映射到同一音高时共享声部，不能算作两条独立复音。配置断开BLE保留，FPGA复位/掉电丢失。
曲谱按物理键编号指引，因此修改键位会改变原曲谱对应的旋律。

### 曲谱

可选择内置半音阶练习，或导入UTF-8 JSON文件，再点“上传并核对全部32步”。
JSON顶层含可选`name`和`events`数组；必须恰好32个事件，每项`key`为0～11或-1（休止），`beats`为1～15，两者都是整数；文件不超过64KB。
不能把不足32步的曲谱直接导入，需补足休止事件。
上传过程为开始、16组双事件写入、校验提交，共18条命令，再读回全部32步。
上传替换曲目0，曲目1/2仍为原练习。曲目指引是跟灯演奏，不会自动播放歌曲。
数据保存在FPGA RAM，BLE断开重连仍保持，FPGA复位/掉电恢复默认。
未接外部LED时可以验证上传和读回，不能据此证明灯光时序正确。
目前只有本地文件导入和蓝牙上传，尚未实现互联网在线曲库。

### 手动录音、下载和删除

1. 录音页点“开始录音”，等待“录音已开始”，再触摸主板演奏。
2. 点“结束录音并下载”，停止采集后自动传输，完整CRC32通过才生成WAV。
3. 播放核对声音和长度，或保存/导出WAV。保留一秒录音和测试C4按钮，测试C4发声5秒、采集其中1秒。
4. 通过“录音管理（播放／导出／删除）”查看各条录音、时长及大小；选择一条播放、导出或删除，也可清空全部录音。

采样率固定46,875Hz、16位、单声道。PSRAM缓存上限30秒，录满自动结束；若PSRAM不可用，内部RAM回退1秒，上限由固件查询显示。
录音是FPGA真实数字输出，含音色及已有音效，不使用手机麦克风。
蓝牙断线会结束录音并保留ESP缓存；重连后“取回板上最近录音”可结束尚在进行的采集并下载。ESP复位/掉电或开始下一次录音会丢弃旧缓存。
采集与下载期间暂停App其他控制，实体触摸演奏独立运行。下载时保持App前台，完成提示会显示耗时。
v0.4每次请求连续通知最多16包，缺包重试，失败可退回兼容下载；用户已反馈速度明显提升，尚未量化倍数。
每次成功下载保存独立时间戳文件，应用重启后可管理；失败不会覆盖先前成功录音。
删除仅作用于应用内部副本，导出到其他目录的文件需用手机文件管理器删除。卸载应用会清除内部录音。

## 新增排查和验收

| 现象 | 检查方法 |
|---|---|
| 旋钮不调音色 | 普通模式菜单0；先按S2再旋转并重新触摸。无效时使用编码器诊断固件 |
| 诊断仅LED0闪、LED2亮，LED1常亮、LED3不亮 | A/77有变化，B/41一直为高；检查B线、插头、共地与模块输出，不据此认定41脚损坏 |
| 诊断后乐器不发声 | 下载正式R9恢复；诊断故意关闭功放和I2S输出 |
| 手机连接不稳定/设备占用 | 断开其他手机App及电脑蓝牙工具，重连本App；此前Windows BLE Explorer不稳定，优先用已验证安卓路径 |
| 录音全静音但CRC正确 | CRC只证明传输一致，检查实际演奏、DATA线和模式；先用测试C4 |
| 录音采集失败 | 检查56→4、55→5、54→6，FPGA是否已下载正式程序；无时钟/溢出会报失败 |
| 显示兼容下载 | 检查是否使用ESP v04和App v0.4；通知重试失败也会回退，手机靠近开发板再测 |
| App删除后手机目录仍有WAV | 那是已导出的副本，使用手机文件管理器删除 |
| 换模式后旋钮功能不同 | 菜单/音色等状态会保留；基础演奏旋转只修改当前菜单参数 |

收尾顺序：先验证3～5秒手动录音和下载耗时，再测30秒自动结束、断线取回、删除/清空、应用重启后列表。
12个LED接入后另做键位、节拍和按对推进验收。
32音测试录音可用于频谱分析；叠层演奏用于展示实际声部联动。完整端到端延迟必须另测，不能拿约1.93微秒的引擎计算时间代替。
后续计划：在线曲库、配置掉电保存、性能展示证据；这些尚未作为功能交付。
